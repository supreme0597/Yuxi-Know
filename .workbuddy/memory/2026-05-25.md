### 确认的关键设计决策
- `messages.id` 为 `Integer, autoincrement=True` → `id >= :target_message_id` 安全
- checkpoint 表操作通过 SQLAlchemy session（非 langgraph_pool）确保与业务表在同一事务
- undo 中先改 `checkpoints.thread_id` 再执行 blob 归档 CTE，利用 changed thread_id 区分保留/归档节点

### SQL 清除重构
- 发现 undo/fork 服务中有约 20 处 `text()` 裸 SQL 调用，用户要求全部清除
- 策略：业务表用 ORM + Python 侧处理（替代 jsonb_set 等），checkpoint 表用 SA table 反射 + expression language
- 新建 `_checkpoint_tables.py`：共享 checkpoint 表反射 + 递归 CTE 构建器（build_descendants_cte / build_ancestors_cte）
- 消息逻辑删除改为 Python 侧加载→修改→flush（替代 jsonb_set SQL）
- 统计重算改为 Python 侧过滤计数（替代 jsonb 字段 SQL 条件）
- blob 归档改为 Python 侧提取 (channel, version) 对 → 集合差 → 逐对 UPDATE
- blob 克隆改为 Python 侧提取唯一对 → 逐对 INSERT
- INSERT...SELECT 改用 SA `insert().from_select()` 模式
- 验证：3 个服务文件零 text() 调用，6 个单元测试通过，前端构建通过
